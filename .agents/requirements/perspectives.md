# Requirement Perspectives

When creating or reviewing requirements, evaluate the feature from all relevant perspectives.

At minimum consider:

- PO — product goals and scope
- BA — business rules and workflows
- UX/UI Designer — user experience and interaction
- Software Engineer — architecture and implementation
- QA — testability and edge cases
- Domain Expert — domain-specific rules and workflows

Examples:

Finance → Accountant / Accounting Manager / Financial Controller

Healthcare → Doctor / Nurse / Healthcare Administrator

E-commerce → Buyer / Seller / Operations

IoT → Device / Network / Operations Engineer

Do not assume that the end user is the only actor.
